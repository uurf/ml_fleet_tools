Blue Osaka Operator Playbook
ブルーショー 大阪 オペレーター手順書
KAGAMI / Tin Drum
Devices: 24 PGH-flashed + ~180 HK ≈ 204 total (HK count + DOA triage TBD — supervisor confirms final number on site) · WiFi: KAGAMI-Blue (TBD — confirm with supervisor) · Show context: KAGAMI_BLUE
対象機: PGHフラッシュ(ピッツバーグで書き込み)済24台 ＋ HK 約180台 ≈ 合計204台（HK の実数・初期故障数は現地でスーパーバイザーが確定）・WiFi: KAGAMI-Blue（仮 — スーパーバイザーに確認）・ショー: KAGAMI_BLUE
Two phases. BLUE devices weren't fully provisioned for this show before shipping (HK 180) or were provisioned for KAGAMI Red (PGH 24). Phase A is a per-device USB-bench precursor that joins them to the BLUE WiFi and enables WiFi ADB. Phase B is the same fleet flow as the Red playbook, run once Phase A is complete on every device.
二つのフェーズ構成。BLUE 対象デバイスは出荷時にこのショー向けプロビジョン未完了のもの（HK 180台）、または KAGAMI Red 用にプロビジョン済のもの（PGH 24台）です。フェーズ A は各デバイスを USB で接続し、BLUE WiFi に接続・WiFi ADB を有効化する事前作業です。フェーズ B は全デバイスでフェーズ A を完了した後に実行する、Red 手順書と同じフリート作業です。
0 · Before you start (one-time per laptop) 0・開始前の準備（ラップトップごとに1回）
Create the KAGAMI_BLUE show config
If your laptop doesn't yet have shows/KAGAMI_BLUE.conf, run ./ml_show.sh init. Answer the prompts with the values supervisor provides:
Show id: KAGAMI_BLUE
SSID: KAGAMI-Blue (confirm with supervisor)
Password: KAGAmius (confirm)
Security: wpa2
Show package, brightness, data dir, expected APK/OS, kiosk version: ask the supervisor running the deploy for current values
Sheets URL: ask the supervisor for the BLUE Apps Script Web App URL
KAGAMI_BLUE のショー設定を作成
ラップトップに shows/KAGAMI_BLUE.conf がまだ存在しない場合、./ml_show.sh init を実行。スーパーバイザーから提供された値をプロンプトに入力します:
Show id: KAGAMI_BLUE
SSID: KAGAMI-Blue（スーパーバイザーに確認）
Password: KAGAmius（確認）
Security: wpa2
ショーパッケージ・明るさ・データディレクトリ・対象の APK/OS、キオスクのバージョン（デプロイ担当のスーパーバイザーに最新値を確認）
Sheets URL（スーパーバイザーに BLUE Apps Script Web App の URL を確認）
Set active show to KAGAMI_BLUE
./ml_show.sh use KAGAMI_BLUE, then ./ml_show.sh — should report Active show: KAGAMI_BLUE.
アクティブショーを KAGAMI_BLUE に設定
./ml_show.sh use KAGAMI_BLUE を実行後、./ml_show.sh を実行してください。Active show: KAGAMI_BLUE と表示されれば正常です。
Show APK and kiosk APK in builds/ when available
Supervisor places the latest BLUE show build and kiosk build in ~/Developer/ml_toolkit/builds/. Phase A can proceed without them — if no APKs are present, Phase A is settings + WiFi only. Phase B re-deploys whenever new builds arrive.
ショー APK・キオスク APK を builds/ に配置（入手次第）
スーパーバイザーが最新の BLUE ショービルドとキオスクビルドを ~/Developer/ml_toolkit/builds/ に配置します。フェーズ A は APK なしでも実行可能（APK が存在しない場合、フェーズ A は設定と WiFi のみになります）。新しいビルドが届き次第、フェーズ B で再デプロイを実行します。
KAGAMI-Blue WiFi broadcasting in the room
SSID: KAGAMI-Blue · Password: KAGAmius (TBD — confirm). Your laptop's WiFi must also be on this SSID for Phase B. Phase A is USB so it doesn't depend on WiFi, but devices need the WiFi to be live when they're powered on.
会場で KAGAMI-Blue WiFi が稼働している
SSID: KAGAMI-Blue・パスワード: KAGAmius（仮 — 要確認）。フェーズ B ではラップトップの WiFi もこの SSID に接続している必要があります。フェーズ A は USB 接続のため WiFi に依存しませんが、デバイス起動時には WiFi が有効である必要があります。
Phase A
USB bench: join BLUE WiFi + enable WiFi ADB
フェーズ A
USB ベンチ: BLUE WiFi への接続＋WiFi ADB の有効化
Throughput. ~5 minutes per functional device including the Allow tap and the manual checklist. With 8 operator stations (4 operators × 2 laptops), ~200 functional devices take ~2.5 hours. One device per laptop at a time. If a HK unit won't boot or won't respond over ADB, set it aside and report to the supervisor — don't burn bench time on hardware faults.
処理速度の目安。正常なデバイス1台あたり約5分（「Allow」許可ダイアログ＋手動チェックリスト込み）。8 オペレーターステーション（4 オペレーター × 2 ラップトップ）で 約200台＝合計約2.5時間。ラップトップ1台につき一度に1台のデバイスの処理。HK の機体が起動しない、または ADB が応答しない場合は、そのデバイスを脇に置きスーパーバイザーに報告してください — ハードウェアの不具合にベンチ時間を費やさないでください。
A · Per device (repeat across stations until every functional unit is done) A・各デバイスごと（全デバイスが正常に動作完了するまで各ステーションで繰り返す）
Connect device to MacBook via USB-C
One device at a time per laptop. Plug the Compute Pack into your USB-C port.
デバイスを USB-C で MacBook に接続
ラップトップ1台につき一度に1台ずつ接続。コンピュートパック（Compute Pack）を USB-C ポートに接続。
Check that the device powers on and shows up
Within ~10 seconds the device should boot and appear in adb devices. If it won't power on, or doesn't show up after a power-cycle and a different USB-C cable, set it aside in the DOA stack and pick up the next unit. Note the carnet/case number for the supervisor.
デバイスが起動し認識されることを確認
約10秒以内にデバイスが起動し、adb devices に表示されるはずです。起動しない、または再起動・USB-C ケーブル交換後も認識されない場合は故障機スタックに脇置きし、次の機体へ進んでください。スーパーバイザー報告用にカルネ/ケース番号を控えてください。
Tap "Allow USB debugging" in the headset (first connect)
For HK devices (never seen this laptop before): a dialog appears in the headset on first connect. Put the headset on, check Always allow from this computer, tap Allow.
For PGH-flashed devices: dialog may not appear (fleet key already trusted). Either way, proceed when the device shows up in adb devices.
ヘッドセット内で「Allow USB debugging」（USB デバッグを許可）をタップ（初回接続時）
HK デバイス（このラップトップに初めて接続するデバイス）の場合、初回接続時にヘッドセット内にダイアログが表示されます。ヘッドセットを装着し 「Always allow from this computer」（このコンピュータを常に許可） をチェック、「Allow」（許可） をタップしてください。
PGH フラッシュ済みのデバイスはダイアログが表示されない場合があります（フリートキーが既に承認済みのため）。いずれの場合も adb devices にデバイスが認識されたら次へ進んでください。
Dismiss "USB Device Detected"
A second dialog appears on every connection regardless of authorization — just tap OK.
「USB Device Detected」（USB デバイスを検出）を閉じる
認証状態に関わらず接続のたびに表示される2つ目のダイアログです。OK をタップしてください。
Run provision (with deploy if builds are ready)
If show + kiosk APKs are in builds/: ./ml_provision.sh --deploy. This applies settings, joins KAGAMI-Blue WiFi, runs the manual-headset checklist gate, installs APKs over USB, then enables WiFi ADB.
If APKs aren't ready yet: ./ml_provision.sh (no --deploy). Settings + WiFi + WiFi ADB only; APK install happens later in Phase B.
プロビジョンを実行する（ビルドが準備できている場合はデプロイも実行）
ショー APK とキオスク APK が builds/ に存在する場合: ./ml_provision.sh --deploy を実行します。設定の適用、KAGAMI-Blue WiFi への接続、手動ヘッドセットチェックリストの確認、USB 経由での APK インストール、WiFi ADB を順に有効化します。
APK が準備されていない場合: ./ml_provision.sh（--deploy なし）を実行します。設定 + WiFi 接続 + WiFi ADB の有効化のみ。APK のインストールはフェーズ B で後ほど実施します。
Confirm the show — press Enter
Prompt: "Press Enter to continue, or S for other available show configurations:". Banner above must show Show: KAGAMI_BLUE. Press Enter.
ショーを確認 → Enter を押す
プロンプトに 「Press Enter to continue, or S for other available show configurations:」 と表示されます。上部のバナーに Show: KAGAMI_BLUE と表示されていることを確認し、Enter を押します。
Enter device tracking info if prompted
If the script prompts for device number / case number / operator initials, fill them in. (Standalone Phase A may not prompt — that's fine.)
プロンプトが出たらデバイス追跡情報を入力する
スクリプトがデバイス番号・ケース番号・オペレーターイニシャルを要求するプロンプトが表示されたら入力してください。（フェーズ A を単体で実行する場合は追跡情報の入力を求めるプロンプトが表示されない場合もありますが、それで問題ありません。）
Complete the manual-headset checklist gate
Script pauses at: "Press Enter when manual steps are complete...". While paused, set these in the headset's Settings, then press Enter:
Battery → Compute Pack Standby: Off
Display → Display Override: Off
Display → Global Dimming: slider just below maximum (level with the "h" in "light" in the text below the setting)
Display → Segmented Dimming: On
Display → Maximum Dimming: slider just below maximum (level with the "l" in "display" in the text above the setting)
System → Advanced → OS Updater: check frequency Never
ヘッドセット手動チェックリストを完了
スクリプトが 「Press Enter when manual steps are complete...」 で一時停止します。停止中にヘッドセットの Settings で以下を設定し、完了後 Enter を押してください:
Battery → Compute Pack Standby: Off（オフ）
Display → Display Override: Off（オフ）
Display → Global Dimming: スライダーを最大のすぐ下まで（設定の下の説明文にある「light」の「h」と同じ高さ）
Display → Segmented Dimming: On（オン）
Display → Maximum Dimming: スライダーを最大のすぐ下まで（設定の上の説明文にある「display」の「l」と同じ高さ）
System → Advanced → OS Updater: 更新確認頻度を Never（しない）に設定
Mark the manual settings in the device tracking sheet
In Kagami Osaka – Device tracker — the tracking sheet your supervisor shared with you — check off the columns you just completed for this device:
Battery: Compute Pack Standby: Off
Display: Display Override: Off
Display: Global Dimming
Display: Segmented Dimming: On
Display: Maximum Dimming
System: Advanced: OS Updater: Check for updates: Never
デバイス追跡シートに手動設定を記録
スーパーバイザーから共有された Kagami Osaka – Device tracker（追跡シート）で、このデバイスについて完了した列にチェックを入れてください:
Battery: Compute Pack Standby: Off
Display: Display Override: Off
Display: Global Dimming
Display: Segmented Dimming: On
Display: Maximum Dimming
System: Advanced: OS Updater: Check for updates: Never
Note the device IP from the final output
The script prints Device IP: 10.x.x.x. Confirm the line WiFi ADB enabled on port 5555 appears. The USB connection drops here — that's expected, the device is on KAGAMI-Blue now.
最終出力からデバイス IP を記録
スクリプトが Device IP: 10.x.x.x を表示します。WiFi ADB enabled on port 5555 の行が表示されていることも確認。ここで USB 接続が切断されますが正常で、デバイスは KAGAMI-Blue に接続済みになります。
Disconnect USB and move to next device
Stage the just-finished device aside (still powered on so it stays on the BLUE WiFi). Pick up the next device, return to step A1.
USB を外し次のデバイスに移る
完了したデバイスは電源を入れたまま脇に置いてください（KAGAMI-Blue WiFi への接続を維持するため）。次のデバイスを手に取り、手順 A1 へ戻ります。
Phase A done across all stations? → Continue to Phase B.
全ステーションでフェーズ A が完了したら → フェーズ B へ進む。
Phase B
Load show assets via SSD
フェーズ B
SSD でショーアセットを転送
Supervisor runs the fleet deploy first. After Phase A, the supervisor connects to the BLUE fleet over WiFi ADB and runs the scan → drift check → APK deploy → dashboard → shutdown chain (see the on-site runbook) — these are not operator steps. Once that's done and the devices are powered off, operators do the per-device SSD asset load below. This is the same loop as the Red playbook.
先にスーパーバイザーがフリートデプロイを実施。フェーズ A の後、スーパーバイザーが WiFi ADB で BLUE フリートに接続し、スキャン → ドリフトチェック → APK デプロイ → ダッシュボード → シャットダウン の一連を実行します（オンサイト手順書を参照）。これらはオペレーターの作業ではありません。完了してデバイスが電源オフになったら、以下の各デバイスごとの SSD アセット転送をオペレーターが行います。Red 手順書と同じループです。
Load BLUE show assets onto each device via SSD SSD から各デバイスへ BLUE ショーアセットを転送
Collect your SSDs and confirm the handoff
Phase A provisioning is done, and the supervisor has deployed the show build and powered the devices off — they're ready for asset load. Collect your BLUE SSDs from the supervisor (about 2 each). You'll keep several devices copying at once — one per SSD you're holding. More SSDs = more devices in parallel.
SSD を受け取り、引き継ぎ状態を確認
フェーズ A のプロビジョンが完了し、スーパーバイザーがショービルドをデプロイしてデバイスを電源オフにしています — アセット転送の準備が整った状態です。スーパーバイザーから BLUE 用 SSD（1人およそ2台）を受け取ってください。手持ちの SSD の数だけ複数のデバイスを同時にコピーできます（SSD 1台につき1デバイス）。SSD が多いほど並列数が増えます。
Attach the SSD to a powered-off device first
Plug the USB-C SSD (BLUE asset payload) into the Compute Pack while the device is off. Attaching before you power on means you won't miss the copy window.
最初にオフのデバイスへ SSD を接続
BLUE アセットが入った USB-C SSD を、デバイスがオフのままコンピュートパック（Compute Pack）に接続します。電源を入れる前に接続しておくと、コピーのタイミングを逃しません。
Power on the device
Hold Power until the LEDs begin the "marching" boot sequence, then release. The Magic Leap logo appears and the device plays its boot sound — this is just the OS booting, not the copy.
デバイスを起動
LED が「流れる」起動シーケンスを開始するまで 電源 を長押しし、離します。Magic Leap のロゴが表示され、起動音が鳴ります — これは OS の起動であり、コピーではありません。
Glance into the headset to confirm the copy started
Right after boot, the BLUE show APK detects the SSD and shows the data folders copying in the display, with its own tones. Look into the headset to see the folders — that, not the boot sound, confirms the copy is running.
The tones help, but with several devices close together they're hard to tell apart, so the glance is the reliable check. If the device goes straight to the splash screen with no copy folders, the SSD wasn't picked up: power off, re-attach the SSD, and power on again.
ヘッドセットをのぞいてコピー開始を確認
起動直後に BLUE のショー APK が SSD を検出し、ディスプレイにコピー中のフォルダーを表示します（コピーの開始音も鳴ります）。ヘッドセットをのぞいてフォルダーを確認してください — 起動音ではなく、これがコピー実行中の合図です。
音も手がかりになりますが、複数のデバイスが近接していると聞き分けが難しいため、目視確認が確実です。フォルダーが表示されないままスプラッシュ画面になった場合は SSD 未検出です。電源を切り、SSD を再接続し、再起動してください。
Move to your next SSD while it copies
You don't need to wait at one device. Once a copy is confirmed running, start the next device with another SSD. Keep as many devices copying as you have SSDs.
コピー中に次の SSD へ
1台のデバイスで待つ必要はありません。コピー実行を確認したら、別の SSD で次のデバイスを開始します。手持ちの SSD の数だけデバイスを同時にコピーし続けてください。
Glance in again for the splash, then remove the SSD
When the copy finishes, the device plays a second set of tones; the BLUE show APK then fully initializes and shows its splash screen. Once the splash appears, detach the SSD.
もう一度のぞいてスプラッシュを確認し、SSD を外す
コピーが完了すると終了音が鳴り、その後 BLUE のショー APK が完全に初期化されてスプラッシュ画面を表示します。スプラッシュが表示されたら SSD を取り外してください。
Place the device in the case/rack — powered on and plugged in
Leave the device powered on and connected to power in its case or rack slot. Do not shut it down.
デバイスをケース／ラックに収納（電源オン・電源接続のまま）
デバイスは電源オンのまま、ケースまたはラックのスロットで電源に接続したままにします。シャットダウンしないでください。
Reuse the freed SSD on the next device; repeat until none remain
The SSD you just removed goes onto the next powered-off device. Keep cycling your SSDs through the fleet until every device assigned to you has been loaded.
空いた SSD を次のデバイスへ。デバイスがなくなるまで繰り返す
取り外した SSD を次のオフのデバイスに使います。担当するすべてのデバイスの転送が終わるまで、SSD を順番に使い回してください。
Report to your supervisor when your batch is done
Tell the supervisor when all your assigned devices are loaded, and flag any device that wouldn't take the copy (no tones/folders even after re-attaching). The supervisor verifies fleet health on the dashboard and makes the go / no-go call.
担当分が完了したらスーパーバイザーに報告
担当する全デバイスの転送が完了したらスーパーバイザーに報告し、再接続してもコピーできなかったデバイス（音もフォルダー表示もない）があれば伝えてください。フリート全体の健全性確認と本番可否の判断はスーパーバイザーがダッシュボードで行います。
Assets loaded — handed off to supervisor.
アセット転送完了 — スーパーバイザーへ引き継ぎ。
