Pittsburgh Fleet — ADB Re-Authorization
One "Always allow" tap per device · 204 devices
KAGAMI / Tin Drum
Why: the 204 devices provisioned in Pittsburgh lost their ADB authorization while shipping — Android revokes it after ~7 days with no connection, even when "Always allow" was checked. Nothing is wrong with the device or the OS. One tap re-authorizes this laptop. The supervisor's sweep afterward disables the timeout so it never happens again.
Before you start (once per laptop)
Laptop is on the latest toolkit
A supervisor has run ./update.sh && ./install.sh — version shows v1.2.5 or later. If unsure, ask before starting.
For each device
1
Connect the Compute Pack to the laptop via USB-C
Use the cable at your station. Wait a moment for the headset to register the connection.
2
Put on / look into the headset → tap the dialog
Allow USB debugging? — check "Always allow from this computer" → tap Allow.
If USB Device Detected also appears, tap OK.
Must check "Always allow"
3
Confirm the laptop sees it as authorized
On the laptop run adb devices — the device must read device, not unauthorized.
Still unauthorized? Re-seat the cable, make sure the headset is awake, and tap the dialog again.
4
Mark the device done & move on
Tick it off on the cart sheet, disconnect the cable, next device. Leave each finished device powered on.
Repeat for all 204 Pittsburgh devices
When a cart is finished — hand off to supervisor
Tell the supervisor which carts are done. They run the network sweep ML_DEV_TEST=1 ./ml_status.sh --fix over WiFi, which sets adb_allowed_connection_time 0 (disable the timeout) on the re-authorized devices — so the authorization never expires again for the run of the show. Newly provisioned devices get this automatically.
