A · Before you start (one-time per laptop) A・開始前の準備（ノートPCごとに1回）
Toolkit installed and up to date
Run cd ~/Developer/ml_toolkit && ./update.sh. If you haven't installed yet, follow docs/setup_checklist.html first.
ツールキットをインストール済み・最新版である
cd ~/Developer/ml_toolkit && ./update.sh を実行。未インストールの場合はまず docs/setup_checklist.html を参照してください。
Shared Fleet ADB key in place
Supervisor provides adbkey_kagami_fleet on a USB drive. Copy to ~/Developer/ml_toolkit/authorized_keys/ and re-run ./install.sh. Look for "Fleet ADB key installed".
共有フリートADBキーが設定済み
スーパーバイザーから配布される USB ドライブ内の adbkey_kagami_fleet を ~/Developer/ml_toolkit/authorized_keys/ にコピーし、再度 ./install.sh を実行。"Fleet ADB key installed" の表示を確認してください。
Active show set to KAGAMI
Run ./ml_show.sh use KAGAMI then ./ml_show.sh — it should report Active show: KAGAMI.
アクティブショーを KAGAMI に設定
./ml_show.sh use KAGAMI を実行後、./ml_show.sh で Active show: KAGAMI と表示されることを確認。
Latest show APK and kiosk APK in builds/
Supervisor places the current Kagami show build and kiosk build in ~/Developer/ml_toolkit/builds/. New builds may arrive multiple times as the show is finalized — always check just before deploying.
最新のショー APK・キオスク APK が builds/ にある
スーパーバイザーが最新の Kagami ショービルドとキオスクビルドを ~/Developer/ml_toolkit/builds/ に配置。ショー本番までビルドは複数回更新される想定です。デプロイ直前に必ず確認してください。
KAGAMI WiFi broadcasting in the room
SSID: KAGAMI · Password: KAGAmius. Devices will auto-join when powered on. Your laptop must also be on this SSID — the fleet operates over WiFi ADB.
会場で KAGAMI WiFi が稼働している
SSID: KAGAMI・パスワード: KAGAmius。デバイス起動時に自動接続されます。フリートは WiFi ADB で動作するため、ノート PC もこの SSID に接続する必要があります。
B · Power up the fleet B・全機の起動
Power on all 180 devices
Hold the Power button on each Compute Pack until the boot indicator appears. Devices were provisioned in Pittsburgh — they boot straight to the kiosk, no OOBE.
180台すべてを起動する
各 Compute Pack の 電源 ボタンを起動表示が出るまで長押し。Pittsburgh でプロビジョン済みのため、OOBE はスキップされ、直接キオスクが起動します。
Devices auto-join KAGAMI WiFi
SSID credentials were saved during Pittsburgh provisioning. No headset interaction needed.
デバイスは KAGAMI WiFi に自動接続される
Pittsburgh でのプロビジョン時に SSID 情報が保存済み。ヘッドセット側での操作は不要です。
C · Inventory the fleet on the network C・ネットワーク上のフリートを確認
Scan the network for ML2 devices
./utilities/ml_scan.sh — finds every device with ADB port 5555 open on the local subnet, prompts to confirm, then writes devices/KAGAMI.txt.
If the auto-detected subnet looks wrong, override: ./utilities/ml_scan.sh --subnet 10.x.x.0/24.
ネットワーク上の ML2 デバイスをスキャン
./utilities/ml_scan.sh を実行。ローカルサブネット上で ADB ポート 5555 が開いているデバイスを検出し、確認後に devices/KAGAMI.txt に保存します。
自動検出されたサブネットが誤っている場合は ./utilities/ml_scan.sh --subnet 10.x.x.0/24 で明示指定。
Confirm device count matches 180
The scan table shows IP / model / serial / OS for each device found. If the count is short: power-cycle the missing devices, wait 30s, and rescan with ./utilities/ml_scan.sh --append.
検出台数が 180 と一致することを確認
スキャン結果に IP・モデル・シリアル・OS バージョンが表示されます。台数が不足している場合は該当機を再起動し、30秒待ってから ./utilities/ml_scan.sh --append で追加スキャン。
D · Drift check before deploying D・デプロイ前のドリフトチェック
Run fleet drift check
./ml_provision.sh --fleet --check. Read-only sweep across every device in devices/KAGAMI.txt. Reports which settings have drifted from the show config (brightness, WiFi, stay-awake, BT, hand nav, etc.).
フリート全体のドリフトチェック
./ml_provision.sh --fleet --check を実行。devices/KAGAMI.txt の全機を読み取り専用でチェックし、ショー設定（明るさ・WiFi・スリープ防止・Bluetooth・ハンドナビ等）からズレている設定を報告します。
If drift is reported, auto-fix
./ml_status.sh --fix remediates stay-awake, Bluetooth, and brightness in one pass. After it finishes, re-run --fleet --check to confirm clean.
Headset-manual items (Display Override, Segmented/Global/Max Dimming, Compute Pack Standby, OS Updater = Never) were set in Pittsburgh and should not have drifted.
ドリフトが報告された場合は自動修復
./ml_status.sh --fix でスリープ防止・Bluetooth・明るさを一括修復。完了後、--fleet --check を再実行して クリーンであることを確認。
ヘッドセット側で手動設定する項目（Display Override・Segmented/Global/Max Dimming・Compute Pack Standby・OS Updater = Never）は Pittsburgh で設定済み、通常はドリフトしません。
E · Deploy the show + kiosk APKs E・ショー APK＋キオスク APK のデプロイ
Verify the right builds are in builds/
Run ls -la ~/Developer/ml_toolkit/builds/*.apk. Look for the show APK (Kagami) and the kiosk APK. If they're stale, ask the supervisor for the latest before deploying.
適切なビルドが builds/ にあるか確認
ls -la ~/Developer/ml_toolkit/builds/*.apk を実行し、ショー APK（Kagami）とキオスク APK の存在・バージョンを確認。古い場合はスーパーバイザーに最新版を依頼してから次へ。
Start the deploy
./ml_deploy.sh deploy. It connects to every device in devices/KAGAMI.txt in parallel, then prints the show banner and the confirm prompt.
デプロイを開始
./ml_deploy.sh deploy を実行。devices/KAGAMI.txt 内の全機に並列接続後、ショーバナーと確認プロンプトが表示されます。
Confirm the show — press Enter
Prompt reads "Press Enter to continue, or S for other available show configurations:". The banner above must show Show: KAGAMI. Press Enter. (If banner shows the wrong show, press S to pick KAGAMI, or Ctrl+C and re-run with the right context.)
ショーを確認 → Enter を押す
プロンプト "Press Enter to continue, or S for other available show configurations:" が表示されます。上部のバナーが Show: KAGAMI であることを確認し、Enter を押します。誤ったショーが表示されている場合は S で KAGAMI を選択、または Ctrl+C で中止し正しいコンテキストで再実行。
Select the APKs to install
The script lists numbered APKs from builds/. Type the numbers separated by spaces (e.g. 1 2 to install both Kagami and the kiosk). Press Enter.
インストールする APK を選択
スクリプトが builds/ 内の APK を番号付きで表示します。スペース区切りで番号を入力（例: 1 2 で Kagami とキオスクを両方インストール）し、Enter を押します。
Wait for install + kiosk-as-home + reboot
The script installs each APK in parallel (up to 20 devices at a time), sets com.tindrum.kiosk as the home app, lets PackageManager persist that, then reboots all devices. End state: Deploy complete. Devices are rebooting.
Typical duration: 5–15 minutes depending on build sizes and AP capacity.
インストール → キオスクをホームに設定 → 再起動 を待つ
スクリプトは各 APK を並列インストール（最大20台同時）、com.tindrum.kiosk をホームアプリに設定し、PackageManager が確実に保存するのを待ってから全機を再起動します。終了表示: Deploy complete. Devices are rebooting.
所要時間: ビルドサイズと AP の負荷次第で 5〜15 分程度。
F · Confirm fleet health via the dashboard F・ダッシュボードで全機の状態を確認
Wait for devices to finish rebooting
Allow ~45 seconds after the deploy completion message before sweeping. ML2 reboot + kiosk launch takes that long.
再起動の完了を待つ
デプロイ完了メッセージから約45秒待ってからステータス取得を開始してください。ML2 の再起動 + キオスク起動にこれくらいかかります。
Generate the status snapshot
./ml_status.sh --json > status/latest.json. Collects OS / APK / kiosk / settings / disk / data-folder state from every device in devices/KAGAMI.txt in parallel.
ステータススナップショットを生成
./ml_status.sh --json > status/latest.json を実行。devices/KAGAMI.txt 内の全機から OS・APK・キオスク・設定・ディスク・データフォルダ情報を並列取得します。
Open the dashboard and load the JSON
Open fleet_dashboard.html in your browser. Click Load JSON (or drag status/latest.json onto the page).
ダッシュボードを開き JSON を読み込む
ブラウザで fleet_dashboard.html を開き、Load JSON をクリック、または status/latest.json をページにドラッグ&ドロップ。
Read the All-OK / Issues / Offline counts
Header shows totals. Goal at this stage: every device online; APK + kiosk versions match the show config; no OFFLINE rows; data-folder rows still red (assets not loaded yet — Section H).
All-OK / Issues / Offline の件数を確認
ヘッダーに合計件数が表示されます。この時点での期待状態: 全機オンライン、APK・キオスクのバージョンがショー設定と一致、OFFLINE 行なし、データフォルダ行は赤（アセット未転送 — セクション H で対応）。
Investigate any unexpected red rows
If a device shows wrong APK version, missing kiosk, or extraneous com.tindrum.* packages — make a note of the IP and report to the supervisor. Don't power-cycle yet; we want diagnosis before remediation.
想定外の赤行を調査
APK バージョンが不一致、キオスク欠落、または余分な com.tindrum.* パッケージが存在する場合は、その IP を記録してスーパーバイザーに報告してください。電源再投入は診断後に行います。
G · Shut the fleet down for asset transfer G・アセット転送のため全機をシャットダウン
Shut down all devices
./ml_deploy.sh shutdown. Powers off every reachable device in parallel. Required because the show APK's SSD-load step only triggers on a fresh power-on with the SSD already attached.
全機をシャットダウン
./ml_deploy.sh shutdown を実行。到達可能な全機を並列で電源オフ。ショー APK の SSD ロード処理は、SSD が接続済みの状態で電源を入れた直後にのみ起動するため、この手順が必要です。
Wait for the fan on each device to stop
A spinning fan means the device is still finishing shutdown. Do not attach the SSD or proceed until the Compute Pack is silent.
各デバイスのファンが停止するまで待つ
ファンが回っている間はシャットダウン中です。Compute Pack が無音になるまで SSD 接続や次の作業に進まないでください。
H · Load show assets per device via SSD H・SSD から各デバイスへショーアセットを転送
One device at a time — timing matters
The show APK looks for an attached SSD at launch. If the SSD isn't attached before the device boots, the copy doesn't start. Order is strict: attach SSD → power on device → put on headset.
1台ずつ作業 — タイミングが重要
ショー APK は起動時にのみ SSD を検出します。起動前に SSD を接続していないとコピーは開始しません。厳密な順序: SSD 接続 → デバイス電源オン → ヘッドセット装着。
Attach the SSD to the device first
USB-C SSD with the Kagami asset payload. Plug into the Compute Pack while the device is still off.
先に SSD をデバイスに接続
Kagami アセットが入った USB-C SSD を、デバイスがオフの状態のまま Compute Pack に接続します。
Power on the device
Hold Power until the boot indicator appears. The kiosk + show APK will launch automatically.
デバイスを起動
起動表示が出るまで 電源 を長押し。キオスクとショー APK が自動的に起動します。
Put on the headset and listen
When the show APK starts copying, you'll hear a start tone series. The headset display shows progress while copying.
ヘッドセットを装着し音を聞く
ショー APK がコピーを開始すると 開始音が連続して鳴ります。コピー中はヘッドセットに進捗が表示されます。
Wait for the finish tone series
When the copy finishes, a second tone series plays. Only then is it safe to remove the SSD.
If you don't hear tones within ~30 seconds of boot: the timing window was missed. Shut the device down, re-attach the SSD, and power on again.
終了音が鳴るまで待つ
コピー完了時に終了音のシリーズが鳴ります。これを聞いてから SSD を外してください。
起動から約30秒経っても音が鳴らない場合はタイミングを逃しています。デバイスをシャットダウンし、SSD を接続し直して再起動してください。
Remove SSD, leave device powered on
Detach the SSD. Do not power the device off — Section I needs it online for the dashboard sweep.
SSD を外し、デバイスは起動したまま残す
SSD を取り外します。電源は切らないでください — セクション I のダッシュボード取得でオンライン状態が必要です。
Move to next device, repeat
Multiple operators can run this in parallel with one SSD per operator. 180 devices × ~3 minutes per device = ~9 device-hours total.
次のデバイスへ、繰り返し
SSD を 1 オペレーター 1 台用意すれば並列作業が可能です。180台 × 約3分 = 合計約9時間相当の作業量。
I · Verify the fleet is show-ready I・ショー本番に向けた最終確認
Re-run the status sweep
./ml_status.sh --json > status/latest.json, then reload fleet_dashboard.html.
ステータススイープを再実行
./ml_status.sh --json > status/latest.json を再実行し、fleet_dashboard.html を再読み込み。
Confirm data-folder rows are now clean
Devices that just received the SSD copy should show the show's data dir populated (no "data missing" red flag). Disk usage may rise — that's expected.
データフォルダ行がクリーンになっていることを確認
SSD コピーが完了したデバイスはショーのデータディレクトリにファイルが配置され、「data missing」赤フラグが消えるはず。ディスク使用量が増えますが想定どおりです。
Report to supervisor
Note the All-OK count, the Issues count, the IP of any device still red, and hand the dashboard view to the supervisor. They decide go / no-go for show.
スーパーバイザーに報告
All-OK 件数・Issues 件数・赤行のデバイス IP を記録し、ダッシュボード画面をスーパーバイザーに引き継ぎます。本番可否の判断はスーパーバイザーが行います。
Red fleet is show-ready.
赤フリート、本番準備完了。
