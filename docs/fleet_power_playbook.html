Fleet Power — Shutdown & Reboot
フリートの電源 — シャットダウンと再起動
KAGAMI / Tin Drum
Power the whole fleet down at end of day, or reboot it when needed. From the show laptop, on the show's WiFi.  ·  一日の終わりにフリート全体の電源を切る、または必要なときに再起動します。ショー用ラップトップから、ショーの WiFi に接続して実行します。
⚑ Set the show first — Red or Blue
Every command below acts on whichever show this laptop is set to. Set it once, then glance at the Show / SSID banner each command prints — wrong show means wrong fleet.
# Red — Studio A cabinets, SSID KAGAMI ./ml_show.sh use KAGAMI # Blue — flight cases, SSID KAGAMI-BLUE ./ml_show.sh use KAGAMI_BLUE
⚑ 最初にショーを設定 — Red か Blue
以下の各コマンドは、このラップトップが設定されているショーに対して実行されます。一度設定し、各コマンドが表示する Show / SSID バナーを毎回確認します — ショーを間違えると対象フリートを間違えます。
# Red — Studio A cabinets, SSID KAGAMI ./ml_show.sh use KAGAMI # Blue — flight cases, SSID KAGAMI-BLUE ./ml_show.sh use KAGAMI_BLUE
On-screen text stays in English.  画面に表示される文字は英語のままです。 Commands and terminal output are kept in English in both columns — that is exactly what appears in Terminal, so it stays matchable. Only the explanation is translated. コマンドとターミナルの出力は、両方の列で英語のままにしています。Terminal に表示されるものと一致させるためです。説明文のみを翻訳しています。（日本語は翻訳者レビュー前の暫定版です。）
Set the show first (box above). On the dev branch, prefix commands with ML_DEV_TEST=1 and skip ./update.sh.  ·  先にショーを設定します（上のボックス）。dev ブランチでは各コマンドの先頭に ML_DEV_TEST=1 を付け、./update.sh は省略します。
End of day — shut down the fleet 一日の終わり — フリートをシャットダウン
1
Confirm network & clear the update gate
Laptop on the show WiFi (a 172.16.40.x address), then run the gate.
./update.sh
Red box Toolkit is out of date = you skipped the gate.
ネットワーク確認とアップデートゲート通過
ラップトップがショーの WiFi（172.16.40.x のアドレス）に接続されていることを確認し、ゲートを実行します。
./update.sh
赤いボックス Toolkit is out of date = ゲートを飛ばしています。
2
Scan if the list is stale
Shutdown acts on the saved device list. If devices were added or moved since the last scan, refresh it first so none are missed. (If you already scanned today, skip this.)
./utilities/ml_scan.sh --yes ./utilities/ml_scan.sh --append --yes
リストが古ければスキャン
シャットダウンは保存済みのデバイスリストに対して実行されます。前回のスキャン以降にデバイスが追加・移動された場合は、漏れがないよう先に更新します。（当日すでにスキャン済みなら省略可。）
./utilities/ml_scan.sh --yes ./utilities/ml_scan.sh --append --yes
3
Shut down the fleet
Powers off every device. It probes the list, sends the shutdown, then re-checks and retries up to 4 passes — so it confirms they actually went off, not just fired the command.
./ml_deploy.sh shutdown
Goal: ✓ All devices powered off. Or: ⚠ N still responding after 4 passes — check physically (with the IP list).
フリートをシャットダウン
全デバイスの電源を切ります。リストをプローブし、シャットダウンを送信し、最大4パスまで再確認・再試行します — コマンドを送るだけでなく、実際に電源が切れたことを確認します。
./ml_deploy.sh shutdown
目標: ✓ All devices powered off。または: ⚠ N still responding after 4 passes — check physically（IP リスト付き）。
4
Mop up any stragglers
A few may not take the command on the first run. Re-run the same command — as devices drop off the wifi frees up and the rest go down. Any that still won't: power off by hand at the cabinet (hold the power button).
./ml_deploy.sh shutdown
Safe to re-run as many times as needed. The leftover few are usually just slow to take the command, not broken.
残りのデバイスを片付ける
最初の実行でコマンドを受け付けないデバイスが数台出ることがあります。同じコマンドを再実行します — デバイスが落ちるにつれ WiFi に余裕ができ、残りも電源が切れます。それでも切れないものは、キャビネットで手動で電源オフ（電源ボタン長押し）します。
./ml_deploy.sh shutdown
何度でも再実行して問題ありません。残る数台は壊れているのではなく、コマンドの受け付けが遅いだけのことが多いです。
When you need it — reboot 必要なとき — 再起動
5
Reboot the fleet
Use to clear a stuck state across the fleet, or when a supervisor asks. (After an APK deploy the reboot is already part of that procedure — see the Deploy playbook; you don't reboot separately for that.)
./ml_deploy.sh reboot
It fires and returns immediately — devices take ~60–90s to come back and rejoin. Wait ~2 minutes before expecting them online.
フリートを再起動
フリート全体の不調を解消したいとき、またはスーパーバイザーの指示があるときに使います。（APK 配信後の再起動はその手順に含まれています — Deploy 手順書を参照。配信のために別途再起動する必要はありません。）
./ml_deploy.sh reboot
コマンドは即座に戻ります — デバイスの復帰・再参加には 約60〜90秒。オンラインを期待する前に約2分待ちます。
Good to know 補足
·
"Still responding" is not a tool failure
It means that device didn't take the shutdown command this pass — re-run, or power it off by hand. Because the tool re-checks each pass, ✓ All devices powered off genuinely means off, not just "command sent."
「Still responding」はツールの失敗ではない
そのデバイスが今回のパスでシャットダウンコマンドを受け付けなかった、という意味です — 再実行するか、手動で電源を切ります。ツールは各パスで再確認するため、✓ All devices powered off は「コマンド送信済み」ではなく、本当に電源が切れたことを意味します。
·
These act on the device list
Both shutdown and reboot work from the saved list, so a stale list can miss recently-added devices. When in doubt, scan first (step 2).
これらはデバイスリストに対して動作する
shutdown も reboot も保存済みのリストに対して動作するため、リストが古いと最近追加されたデバイスを取りこぼすことがあります。不安なときは先にスキャン（手順2）します。
