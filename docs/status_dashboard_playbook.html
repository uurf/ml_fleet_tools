Morning Status & Dashboard
朝の status とダッシュボード
KAGAMI / Tin Drum
Run each morning to read the fleet's health and surface any device that needs attention before the show. From the show laptop, on the show's WiFi.  ·  毎朝実行し、フリートの状態を確認して、ショー前に対応が必要なデバイスを洗い出します。ショー用ラップトップから、ショーの WiFi に接続して実行します。
⚑ Set the show first — Red or Blue
Every command below acts on whichever show this laptop is set to. Set it once, then glance at the Show / SSID banner each command prints — wrong show means wrong fleet.
# Red — Studio A cabinets, SSID KAGAMI ./ml_show.sh use KAGAMI # Blue — flight cases, SSID KAGAMI-BLUE ./ml_show.sh use KAGAMI_BLUE
⚑ 最初にショーを設定 — Red か Blue
以下の各コマンドは、このラップトップが設定されているショーに対して実行されます。一度設定し、各コマンドが表示する Show / SSID バナーを毎回確認します — ショーを間違えると対象フリートを間違えます。
# Red — Studio A cabinets, SSID KAGAMI ./ml_show.sh use KAGAMI # Blue — flight cases, SSID KAGAMI-BLUE ./ml_show.sh use KAGAMI_BLUE
On-screen text stays in English.  画面に表示される文字は英語のままです。 Commands, file names, column headers, and on-screen labels are kept in English in both columns — that is exactly what appears in Terminal and in the dashboard, so it stays matchable. Only the explanation is translated. コマンド・ファイル名・列見出し・画面のラベルは、両方の列で英語のままにしています。Terminal やダッシュボードに表示されるものと一致させるためです。説明文のみを翻訳しています。（日本語は翻訳者レビュー前の暫定版です。）
Set the show first (box above). On the dev branch, prefix commands with ML_DEV_TEST=1 and skip ./update.sh.  ·  先にショーを設定します（上のボックス）。dev ブランチでは各コマンドの先頭に ML_DEV_TEST=1 を付け、./update.sh は省略します。
Collect the status status を取得
1
Power up & confirm the network
Cabinets on, AP broadcasting the show SSID, laptop on it (or wired to the same subnet). Give devices a couple minutes to boot and join.
ipconfig getifaddr en0
Laptop should have a 172.16.40.x address.
電源を入れてネットワークを確認
キャビネット（cabinets）の電源を入れ、AP がショーの SSID を発信し、ラップトップが同じネットワーク（または同一サブネットの有線）に接続されていることを確認します。デバイスの起動と参加まで数分待ちます。
ipconfig getifaddr en0
ラップトップが 172.16.40.x のアドレスを持っていること。
2
Clear the update gate
Pulls the latest toolkit and protects the shared fleet key, so everyone runs the same version.
./update.sh
If you see the red box Toolkit is out of date, you skipped this.
アップデートゲートを通過
最新のツールキットを取得し、共有のフリートキーを保護します。全員が同じバージョンで実行するためです。
./update.sh
赤いボックス Toolkit is out of date が出たら、この手順を飛ばしています。
3
Scan — run until the count stops growing
Refresh the device list. One pass undercounts; run it, then --append until the number is stable.
./utilities/ml_scan.sh --yes ./utilities/ml_scan.sh --append --yes
Count settles (≈183 for red) and stops growing.
スキャン — 台数が増えなくなるまで実行
デバイスリストを更新します。1回では台数が不足するため、実行後に --append を台数が安定するまで繰り返します。
./utilities/ml_scan.sh --yes ./utilities/ml_scan.sh --append --yes
台数が安定（RED は約183）して増えなくなること。
4
Run status to a JSON file
This is what feeds the dashboard. status re-probes and connects on its own — no connect needed. The on-screen summary already tells the story; the JSON file is for the dashboard.
./ml_status.sh --json > status/latest.json
Read the summary line: Total / All-OK / Issues / Error / Offline. They should add up to the device count.
status を JSON ファイルに出力
これがダッシュボードの入力になります。status は自身で再プローブ・再接続するため、connect は不要です。画面のサマリーだけでも状況は分かります。JSON ファイルはダッシュボード用です。
./ml_status.sh --json > status/latest.json
サマリー行を確認: Total / All-OK / Issues / Error / Offline。合計がデバイス台数と一致すること。
Load & read the dashboard ダッシュボードを読み込んで確認
5
Open the dashboard
Opens fleet_dashboard.html in the browser. It starts empty — you load today's data into it.
open fleet_dashboard.html
ダッシュボードを開く
ブラウザで fleet_dashboard.html を開きます。最初は空です — 当日のデータを読み込みます。
open fleet_dashboard.html
6
Load JSON, then load CSV
Click Load JSON and pick status/latest.json — the rows fill in. Then click Load CSV and pick asset_serial_list.csv — that fills the Device # column. (Re-load the JSON after every new status run; the dashboard doesn't auto-refresh.)
Load JSON、続いて Load CSV
Load JSON をクリックして status/latest.json を選ぶと、行が表示されます。次に Load CSV をクリックして asset_serial_list.csv を選ぶと、Device # 列が埋まります。（status を実行するたびに JSON を読み込み直します。ダッシュボードは自動更新しません。）
7
Read the board — green is good
Green rows are healthy. Flagged rows mean: wrong OS or app, kiosk wrong/missing, data-folder problem, /sdcard nearly full, hand-nav off, low battery, or OFFLINE. Use the filter dropdown to isolate one issue type.
OFFLINE = the device didn't answer this run. Re-run status — most rejoin. If one stays offline but is powered and running, note it for the supervisor.
ボードを読む — 緑が正常
緑の行は正常です。flag された行の意味: OS または app が不正、kiosk が不正/欠落、データフォルダの問題、/sdcard の空き不足、ハンドナビ オフ、バッテリー低下、または OFFLINE。フィルター（filter）で特定の種類だけ表示できます。
OFFLINE = その実行でデバイスが応答しなかった。status を再実行するとほとんど復帰します。電源が入って動作しているのに offline のままなら、デバイス# を控えてスーパーバイザーへ。
8
Escalate what you can't clear
A device that's still flagged after a re-run — wrong build, missing data, won't come online — goes to the supervisor with its Device # and serial. The morning job is to surface problems, not necessarily fix them.
解決できないものはエスカレーション
再実行しても flag が残るデバイス（不正なビルド、データ欠落、オンラインにならない等）は、Device # と serial を添えてスーパーバイザーへ。朝の作業は問題を洗い出すことが目的で、必ずしも修正までは行いません。
Good to know 補足
·
Each status run is a fresh live read
status and status --json each re-probe the whole fleet from scratch, so two runs minutes apart can differ — a device can be online in one and offline in the next. That's normal. Re-run to confirm before acting, and don't chase a single flapping device's flags.
各 status は毎回ライブで取得
status も status --json も、毎回フリート全体をゼロから再プローブします。そのため数分違う2回の実行で結果が異なることがあります — あるデバイスが片方で online、もう片方で offline になることも。これは正常です。対応前に再実行して確認し、1台だけ不安定なデバイスの flag は追いすぎないようにします。
